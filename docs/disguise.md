# 伪装与反识别策略（Anti-Detection Playbook）

> 目标：让"这个账号在发消息"这件事，在频率、时间、内容、关系四个维度上都更像一个真人，
> 从而降低被判定为自动化、被限制或被封禁的概率。
>
> 边界：这是概率工程，不是免死金牌。客户端注入的静态特征、账号历史、被举报，
> 都不是应用层能完全消除的。本文档同时给出"做不到的部分"，便于评估残余风险。

## 0. 一句话结论

封号通常不是因为"检测到 `version.dll`"，而是因为**行为像机器**：
秒回、24 小时在线、每条都长、句句带 Markdown、对不同的人说同样的话、短时间高频输出。
所以伪装的投入应该按这个顺序分配：

```text
行为节奏  >  内容文风  >  会话关系  >  网络出口  >  客户端/进程
```

本文的实现重心在前三项，第四、五项给出可执行的加固清单。

## 1. 威胁模型：风控在看什么

### 1.1 服务端行为信号

| 信号 | 机器特征 | 真人特征 | 本项目的处理 |
|---|---|---|---|
| 发送频率 | 每分钟固定条数、整点爆发 | 忽快忽慢、成簇 | 四窗口配额 + 爆发冷却 |
| 响应延迟 | 恒定 1~2 秒、方差极小 | 右偏分布、受内容长度影响 | 读+想+打字模型 |
| 在线时间 | 7×24 全时段均匀 | 有睡眠、午休、离开 | 睡眠窗口 + 手动离线块 |
| 消息长度 | 每条都 300+ 字 | 大多 10~60 字 | 分条 + 总长截断 |
| 会话并发 | 多会话同一秒 | 一次只聊一个 | 同一会话串行 + 抖动 |
| 主动行为 | 定时群发、批量打招呼 | 偶尔、随机 | 默认不主动 |

### 1.2 内容信号

- **结构词**："首先/其次/最后/总之/综上/需要注意的是" —— 模型最稳定的指纹之一。
- **排版残留**：`**加粗**`、`- 列表`、`### 标题`、代码围栏、表格。
- **自我暴露**："作为 AI / 作为一个语言模型 / 我是助手"。
- **模板开头**："好的，我来帮你……"、"当然可以！" 每次一样。
- **模板结尾**："希望这对你有帮助"、"如果还有其他问题，随时告诉我"。
- **完美标点**：每句都以"。"结尾、中英文标点严格。
- **跨会话复读**：同一天对不同人发同一段话 —— 群发判定里权重很高。

### 1.3 账号与设备信号

- 新注册/低活跃账号突然高频发送
- 登录地、设备指纹、客户端版本频繁变化
- 短时间大量加好友、被拉黑、被举报
- 同一设备/IP 登录多个账号

### 1.4 客户端本地特征（应用层难以完全消除）

- 目录内多出的非腾讯签名 DLL（sideload）
- 进程模块列表、监听端口、命名管道
- 客户端完整性校验、异常调用栈

### 1.5 负反馈

举报、拉黑、投诉是权重最高的信号，一次举报可能抵掉几个月的"正常行为"。
**内容不要引起对方反感**，比任何技术伪装都有效。

## 2. 分层策略

### L0 账号层

| 项 | 做法 |
|---|---|
| 养号 | 新号前 7 天只做低强度真人操作，不接机器人 |
| 单账号单设备 | 一个微信号固定一台机器、一个客户端版本 |
| 资料完整 | 头像、昵称、地区、朋友圈不要空白得像小号 |
| 好友来源 | 优先已有真实关系，不做批量添加 |
| 版本稳定 | 锁定 `4.1.10.27`，不随意升级/降级 |

### L1 客户端与进程层

| 项 | 做法 | 落地 |
|---|---|---|
| 端口收敛 | Hook 只监听回环，防火墙阻断 `30001` 局域网访问 | `install-hook.ps1 -ConfigureLoopbackFirewall` |
| 无控制台 | 用 `javaw.exe` 启动，不留黑窗口 | `scripts/start-stealth.ps1` |
| 进程低调 | 服务 JAR 改名（如 `wxsync.jar`），命令行不带业务关键词 | 同上 |
| 启动抖动 | 开机后随机延迟 0~90 秒再启动，不固定秒级 | 同上 |
| 日志收敛 | 输出到用户目录文件，异常不弹窗 | 同上 |
| DLL 来源 | 固定上游版本 + SHA-256 校验，安装前备份原文件 | `windows-agent/prebuilt/manifest.json` |

### L2 网络层

- 出口 IP 固定：不要中途切代理、VPN、热点。
- 不要用机房/云主机 IP 直接挂个人微信；家宽/办公网更自然。
- 多账号不同 IP、不同设备、不同活跃时段。
- DNS、时区、系统语言保持稳定，不要今天 UTC 明天北京。

### L3 行为节奏层（本项目核心，`app.disguise.*`）

1. **读消息延迟**：1.2~7 秒，幂分布（多数很快，少数很慢）。
2. **思考时间**：0.5 秒起，按字数增加，封顶 4.5 秒。
3. **打字时间**：字数 ÷ 手速，手速按会话稳定在 2.9~4.4 字/秒，再叠高斯抖动。
4. **昼夜节律**：23:00~07:00 ×1.65，07:00~09:00 ×1.35，午休 ×1.25，22:00 后 ×1.3。
5. **睡眠窗口**：默认 `00:30-07:30`，期间的消息全部推迟到醒来 + 5~100 秒随机。
6. **手动离线块**：由管理员在“发信节奏”页面维护每日时间段，独立开关控制是否启用；最多 6 段，支持跨零点，保存后立即生效。
7. **长停顿**：8% 概率额外 15~180 秒（"去忙别的了"）。
8. **离开**：2% 概率额外 4~15 分钟。
9. **分条**：长回复按句切成 1~3 条，条间隔 0.6~2.6 秒 + 下一条字数×8ms。
10. **配额**：单会话 3/分钟、8/10 分钟、20/小时、120/天；全局 40/小时、220/天。
11. **爆发冷却**：10 分钟内发满 5 条，强制休息约 1.5~4 分钟。
12. **串行发送**：同一会话同一时刻只允许一条在途，杜绝"两条同时弹出"。

### L4 内容层

- 后处理清洗：Markdown、结构词、AI 自称、客套结尾、`您`→`你`、破折号、多余表情。
- 句末句号默认去掉（微信口语习惯），保留 `！` `？` `…`。
- 总长截断到 420 字以内，按句边界切。
- 系统提示追加"微信口语约束"，与后处理形成双保险（模型层 + 代码层）。
- 复读检测：3-gram Jaccard，同会话 > 0.62 或跨会话 > 0.92 触发"换说法重答"。
- 表情上限 1 个/条；不主动发链接、二维码、文件、小程序。

### L5 会话关系层

- 只处理白名单会话（`WECHAT_ALLOWED_CHATS`），不碰陌生人和大群；公众号、机器人和微信系统会话永不回复。
- 群聊仅在命中唤醒词时回复，且延迟 ×1.35（要先看上下文）。
- 私聊优先，群聊降频；同一群 10 分钟内最多 8 条。
- 默认不做主动群发；如启用主动聊天，必须带随机抖动与安静时段。
- 不 @全体成员，不在群里发长文，不在深夜接话。

### L6 观测与熔断

| 指标 | 正常范围 | 熔断动作 |
|---|---|---|
| P95 回复延迟 | 8~40 秒 | 过低说明伪装失效，检查配置 |
| 分钟发送曲线 | 双峰、有空白 | 过于均匀则加大抖动 |
| 同会话重复率 | < 5% | 调低相似度阈值 |
| 跨会话相似命中 | 0 次/天 | 立即检查是否在群发 |
| 发送失败率 | < 2% | 连续失败即停机，避免重试风暴 |
| 被限制/被举报 | 0 | 停 24~72 小时，人工接管 |

### 3.4 管理接口

```powershell
$h = @{ Authorization = "Bearer $env:ADMIN_TOKEN" }

# 当前状态：在线/睡眠、下次活跃时间、配额、最近 40 次决策
Invoke-RestMethod http://localhost:8080/api/admin/disguise -Headers $h

# 预览：给定一段模型输出，看会被怎么洗、怎么拆、延迟多少（不占配额）
$body = @{ chatId = "wxid_demo"; chatType = "PRIVATE"; text = "**好的**！首先，我为您整理如下：`code`" } | ConvertTo-Json
Invoke-RestMethod http://localhost:8080/api/admin/disguise/preview -Method Post -Headers $h -ContentType "application/json" -Body $body

# 手动更新“离开手机”离线块（立即生效并持久化）
$body = @{ enabled = $true; blocks = @("10:00-10:40", "15:00-15:40") } | ConvertTo-Json
Invoke-RestMethod http://localhost:8080/api/admin/disguise/away-blocks -Method Put -Headers $h -ContentType "application/json" -Body $body
```

## 4. 延迟模型

单条消息的发送时刻：

```text
T = clamp( read + think + typing ) × circadian × group_factor + pause + away
read    ~ min + (max-min) · U²           # 幂分布，右偏：多数秒读，少数很久
think   = 500ms + min(4500ms, 9ms/字)
typing  = 字数 / 手速 × (1 + N(0, 0.30))  # 手速按会话稳定
pause   ~ 8% 概率 U(15s, 180s)
away    ~ 2% 概率 U(4min, 15min)
clamp   → [0.8s, 90s]
```

为什么不用均匀分布：真人反应时间是右偏的（大多数很快，少数很慢）。
均匀分布反而会产生"每条都 3.0 秒"这种机械感。

## 5. 与 WeChatAgent 的对照

参考项目（`D:\WeChatAgent-main`）已经做了几件对的事，本项目保留并在其上补齐：

| 能力 | WeChatAgent | 本项目 | 说明 |
|---|---|---|---|
| 消息聚合窗口 | `batch_ms=3000` | 读延迟 + 分条 | 我们不打固定批窗口，改为逐条延迟 |
| 会话最小间隔 | `min_interval_ms=15000`（群）/1000（私聊） | 1.2 秒起 + 打字模型 | 固定 15 秒本身也是指纹 |
| 频率上限 | 3/分钟、10/10 分钟 | 3/分钟、8/10 分钟 + 小时/天/全局 | 增加长窗口，防"细水长流式群发" |
| 分条 | 最多 2 条，空行分隔 | 最多 3 条，按句打包 | 更接近真人打字的换行习惯 |
| 人格 | 角色卡强调"短句、像打字" | 系统提示 + 后处理双保险 | 模型不听话时由代码兜底 |
| 主动聊天 | `jitterMinutes=15` | 睡眠 + 离线块 + 抖动 | 主动消息最容易被判定，需更保守 |
| 冷却 | 有 | 有 + 爆发冷却 | 连续对轰时强制休息 |

本项目额外补的：

1. 昼夜节律与睡眠窗口（参考项目只限制主动聊天的时段）。
2. 可手动配置的离线块，避免"永远在线"，并提供独立开关。
3. 跨会话相似度检测（群发特征），参考项目只在单会话内去重。
4. AI 味评分与文风清洗（把"首先/总之/Markdown"在发送前就删掉）。
5. 按会话稳定的打字手速指纹（同一联系人长期一致，不同联系人不同）。
6. 同会话串行发送（防止两条气泡同一毫秒弹出）。
7. 管理端预览接口，可在不打扰真实联系人的情况下调参。

## 6. 账号运营手册

### 6.1 新号 7 天曲线

| 天数 | 私聊回复/天 | 群聊回复/天 | 主动消息 | 备注 |
|---|---|---|---|---|
| 1-2 | ≤ 20 | 0 | 禁止 | 只接熟人，不主动 |
| 3-4 | ≤ 40 | ≤ 10 | 禁止 | 观察是否有"操作频繁"提示 |
| 5-7 | ≤ 60 | ≤ 20 | ≤ 2 | 逐步放开 |
| 8+ | 按 `per-day` 配置 | 按 `per-day` | 谨慎 | 保持曲线有起伏 |

### 6.2 日常

- 只回不主动；主动消息控制在每天个位数。
- 群聊只在被 @ / 命中唤醒词时说话，且不超过 8 条/10 分钟。
- 不@全体、不发链接/二维码/文件/小程序、不谈钱。
- 遇到"操作频繁，请稍后再试"：立即停 24 小时。
- 遇到限制登录/被封：停 72 小时，人工检查内容与举报来源后再恢复。
- 多账号：一机一号一 IP，不同人设、不同活跃时段，避免同一天注册。

### 6.3 参数基线

| 场景 | per-minute | per-10min | per-day | 延迟 | 分条 |
|---|---|---|---|---|---|
| 保守（新号/敏感期） | 1 | 3 | 40 | ×1.5 | 最多 2 |
| 标准（稳定号） | 3 | 8 | 120 | 默认 | 3 |
| 激进（内部测试） | 5 | 15 | 300 | ×0.6 | 4 |

- [ ] 备份了原始 `version.dll`

## 8. 做不到的部分

必须明确，避免产生"已经安全"的错觉：

1. **客户端静态特征**：sideload 的未签名 DLL、模块列表、监听端口，本地风控若做完整性校验仍可能发现。
2. **行为之外的历史**：账号年龄、实名信息、设备指纹、历史违规记录，应用层无法修改。
3. **举报**：一次针对性举报的权重远高于几个月的"正常行为"，只能靠内容不惹人来降低。
4. **平台规则**：个人微信不提供机器人协议，任何 Hook 方案都处在灰色地带，规则变化可能导致方案整体失效。

因此建议：灰度上线、保留人工接管开关、设置每日硬上限、出现异常立即停机，
把"被发现"当成必然事件来设计降级路径，而不是假设它不会发生。
